第六阶段：资料库前端（2026-10-22）

当前结果

在现有静态JSON API上增加真实可用的资料库前端。默认进入资料导航首页，八类实体均可检索和打开详情；重点完成
武器等级性能/配方 → 道具素材 → 采集出处/奖励 → 地图点位的连续查询。
源代码在web/，可部署产物在games/mhxx/，与上层网站一起从main分支根目录发布。

视觉与交互约束

白色面板、极浅灰背景、小面积绿色强调；桌面标题22px，小屏18px，正文以12～13px为主。
分类侧栏、紧凑表格、清晰分隔；不设置宣传型首屏或大标题。
微交互包括悬停阴影、按钮按压、链接预览、骨架加载、结果淡入、标签下划线，以及浏览器
支持时的武器等级View Transitions。prefers-reduced-motion会关闭动画。
项目AGENTS.md规定：页面和任何控件都必须适配屏幕宽度，禁止横向滚动，也不能靠裁切或丢弃数据掩盖溢出。
窄屏改用折叠分类导航，详情侧栏下移；表格按容器宽度紧凑排列，页签与筛选自动换行。
以320px及以上手机宽度作为窄屏设计基准；没有使用设备模拟器或浏览器控制验收。

功能

首页沿用原版实用的分类目录，去掉新闻：14种武器、关键任务与村/集会所/G级任务、
素材分类、防具稀有度、技能、24张地图和按种族分组的怪物名单。收藏与最近浏览按需显示。
73个细分类别的成员直接从原页面提取，点击进入准确的新版筛选列表，不以名称搜索代替。
前端导航仅保留内部页面。移除50个原站外跳入口（猫饭、随从猫、武器操作、狩技、交易、装饰品等），
对应空分组和空面板一并移除；这些内容尚未迁移，不能把入口删除视为功能已经补齐。
删除详情来源面板、查看原始页面、无脚本外跳和重复的来源提示；源地址、来源哈希和差异记录仍保留在数据层。
怪物肉质等有效说明改称“数据说明”，防具描述改称“装备说明”；保留相对强度、概率参考和待核对数值提示。
地图中仅适用于旧配色或旧链接的说明不再显示，保留采集概率参考提示。武器性能详情仍可展开查看。
左上角标识、侧栏“资料首页”或#home均可返回首页；已有详情和分类深链接继续可用。
怪物目录保留23个[新]/[再]标记，龙种使用独立标题条；名称固定网格排列，宽屏4列、窄屏2列。
怪物相关任务展示任务目标、地点、同场怪物、数量与乱入标记，并恢复原站体力/全体防御强度条。
怪物详情先显示奖励，再显示相关任务，两块同时可见，不再通过页签二选一。
奖励和任务独立分页；奖励难度筛选仅重置奖励页，不影响任务列表，旧页签深链接继续有效。
强度条是原站换算后的相对刻度，不是实际HP或防御率，缺失值仍显示未记载。
奖励表、十列肉质表都固定在面板宽度内，名称和特殊状态数值自动换行。
任务表参照原站合为任务/目标、出现怪物、相对强度三列，地点和难度并入任务列。
素材采集表合为四列，保留地图、难度、点位、次数、条件、数量与概率。
全局检索列表合并概览字段，手机上不再隐藏补充信息列。
任务列表概览直接显示主目标、怪物数量及狩猎/捕获/讨伐等条件；全部大型怪物的狩猎任务
补充原站记载的具体怪物名单，排除乱入。地点和关键任务标记保留在下方，长目标自动换行。
采集任务显示交纳等原始目标；原站缺失目标的任务明确标注未记载，仅列出已知出现怪物。
任务列表提供村、集会所（含G级）、特殊许可、斗技大会、挑战和活动分类，支持与星级/难度、
狩猎/捕获等任务类型组合过滤。关键任务122个、紧急任务29个，另提供“关键＋紧急”合并筛选。
首页原有关键任务目录继续包含关键和紧急两类；筛选会显示当前状态，修改条件回到第1页。
分类来自任务目录，标记来自任务详情；不通过任务名称猜测是否关键。委托资料本次不提取。
地图详情末尾列出该地图的全部任务，每页40条，展示名称、目标、昼夜地点和标记，并可打开任务详情。
任务列表独立于采集区域/难度；按原站目的地链接精确关联，不通过名称猜测或仅筛选当前采集难度。
1329个任务关联到24张地图；另8个任务的原站目的地没有地图页面链接，保留原值，不强行归类。

武器分类默认进入对应类型的派生树。支持全部等级、仅最终、LV1、LV1·最终、
LV1·派生·最终五种模式，分支可逐个收起或重新展开。列表与详情等级表采用原站的五列结构：名称、攻击、性能、斩味/远程性能、孔槽。
展开按钮和收藏置于名称栏，会心、属性与防御集中在性能栏。每行直接显示对应等级的攻击、会心、
属性、防御加成、基础/匠+2斩味与孔槽；弓和弩显示蓄力/装填性能。
斩味使用同一180px来源基准换算成百分比，不会把不同长度的基础/匠+2色条各自拉满。
斩味沿用原站七色，背景与边框使用纯黑，提升蓝斩等颜色与空余段的明度对比。
孔槽使用可伸缩的三格符号：绿色实心圆表示有孔，灰色短横杠表示无孔。
武器树保留完整层级和分支引导线，按名称栏宽度分配最多36%的缩进空间，
每一级都保留独立差距，宽屏每级最大14px；收起分支不会改变其余节点的缩进尺度。
支持本类名称/别名和属性筛选；最终武器可按攻击或名称排序。筛选保留必要的父级路径，
树模式每页6棵完整派生树，最终模式每页40把武器。点击名称直达该等级配方。
详情页显示原站记载的派生来源和分支，并可直接跳转到所属的完整派生树。
最终沿用原站每条路线的最后一级分类，包括仍可向其他路线派生的锈蚀武器。

防具目录默认折叠单件，显示套装名和通用一组或剑士/射手两组的合计。
四列依次为类型/名称、防御（初始/最高）、技能点、孔；展开后各件数据按职业分组，
单件孔槽使用一行三个圆点/短横杠，套装合计使用总孔数。可单套或全部展开/折叠。
支持12个原站稀有度分类、通用/剑士/射手筛选、名称/单件别名/技能检索和名称排序；
每页20套，始终保持同一套的两个职业版本在一起。点击单件进入详情并标出对应部件。
防具详情也按职业分组，保留技能点、耐性和配方；武器详情孔槽不再被标签样式覆盖为竖排。
原站656套、5685件、1252组汇总均已核对；身体系统加倍仍作为独立点数列出，
不擅自将其计入其他技能的合计。目录约2.46MB，仅进入防具列表时加载并在会话内缓存。

1. 全局名称/别名检索（含升级武器名及单件防具名）、分类筛选、武器类型筛选、名称/最高攻击排序。
2. 武器全等级属性、双值会心、原比例斩味条、逐等级配方与费用差异说明。
3. 素材基础资料、采集/奖励/武器用途/防具用途/调合关系；按地图、难度过滤，完整分页。
4. 地图区位/难度切换、普通/稀有点位、素材概率、采集次数；原始概率合计异常继续保留。
5. 怪物肉质及奖励、任务目标及关联、防具部件/耐性/配方、技能发动条件、调合成功率。
6. 当前浏览器的收藏夹、最近浏览、复制当前链接；不需要账号，不上传个人浏览记录。
7. Cmd/Ctrl+K或/聚焦搜索，Esc收起分类/预览；交互状态保存在URL，可刷新或复制深链接。
8. 空结果、缺值、无独立道具页、请求失败及版本不一致有明确提示，不编造来源字段。

实现选择

使用原生ES模块和CSS；线上无框架包、构建运行时或外部CDN依赖。
约1.75MB的完整浏览索引由构建脚本从实体数据生成，含列表轻量字段、原站分类归属及任务目的地标识。
首页仅按需读取约57KB的home-data.json导航数据，不加载完整浏览索引。
导航构建保留原首页及73个分类来源页的哈希，可追踪目录和分类成员的来源。
全局名称归一化、筛选、排序与分页在Module Worker中执行；不支持Worker时退回同一检索函数。
武器派生目录按14种类型独立加载，每类约244～437KB；包含10911级、798条跨路线派生和
794棵树。只加载当前类型，筛选直接在已缓存的小目录中完成，不逐个请求武器详情。
详情按需读取，加载结果缓存；异步导航通过序号保护，旧请求不会覆盖当前页面。
素材筛选前会完整读取所选关系的全部数据页，防止只过滤前100条的错误；结果每页40条。
API与索引的数据版本必须一致。地图和点位图片从本地旧站复制，不依赖在线原站加载。
hash路由及相对资源地址可用于GitHub Pages子目录；数据/前端以同一静态目录提供服务。

构建和启动

已生成静态API时：
  .venv/bin/python scripts/frontend.py build
  .venv/bin/python scripts/frontend.py verify
  .venv/bin/python scripts/frontend.py serve --port 8766

启动后打开：
  http://127.0.0.1:8766/games/mhxx/

直达武器：
  http://127.0.0.1:8766/games/mhxx/#id=weapon%3Asite-218099&level=3

预览默认绑定0.0.0.0，局域网设备可通过本机局域网IP与8766端口访问，Ctrl-C停止。
显式启动：.venv/bin/python scripts/frontend.py serve --host 0.0.0.0 --port 8766
需要仅本机访问时使用--host 127.0.0.1；--prefix可更换子目录挂载点。
构建输出约116MB文件内容（含完整API），首屏不下载整个包。
页面代码与样式合计约130KB，浏览索引约1.75MB；首页导航、武器目录、详情及关联按需读取。
新版构建输出直接占用games/mhxx/，旧版移至games/mhxx_old/，不在新版导航中提供入口。
旧站仅将index.html中写死的线上跳转改为index/；其余HTML和资源保持原样，继续用于提取。
上层电脑/手机导航已有的mhxx/index.html地址直接进入新版，站点上层保持原样。
兼容旧首页/games/mhxx/index/；具体旧资料页的URL暂未逐条映射。
完整网站保留上层原有文件，main以新的初始提交开始。旧站归档没有访问限制。
构建在任务临时目录完成，验证后替换已知产物；发现用户文件或损坏产物拒绝覆盖。

测试

Python环境沿用数据管道。前端运行无需npm依赖；DOM测试使用锁定版本happy-dom，
在Node内存中执行页面逻辑，所有请求映射到本地静态包。它不启动、安装或操作真实浏览器。

首次安装测试依赖：
  npm ci --ignore-scripts

构建后执行：
  .venv/bin/python -m pytest -q
  npm test

Python测试核对6577实体、源码/产物哈希、API副本、嵌套HTTP路径和资源MIME。
Node测试核对原站分类成员、别名/全角检索、过滤/排序/完整分页、转义/缺值、收藏以及八类详情页面。
DOM集成测试先检查默认首页、任务/矿石分类、返回首页和收藏快捷入口，再执行
搜索 → 武器LV3 → 圆盘石 → G位筛选 → 地图，并验证337条药草
记录已读到第4个API数据页、页面翻页、收藏持久化、快捷键和404错误提示。
各页面状态检查导航不跳出本站、不显示来源提示；首页无空分组，怪物状态等实质说明继续保留。

验证边界

按用户约束，默认不使用Computer Use。真实浏览器的视觉排版、动画表现和不同浏览器
兼容性尚未进行人工/图形验收。自动化DOM测试不等于视觉验收。
目前仍沿用原站混合中文/日文字段；数据差异和未抽取领域见前五阶段文档。
弩/弓的部分专属字段仍显示在原始性能记录中，尚未单独设计全部专属字段的可视化。
